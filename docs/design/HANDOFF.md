# 시간 암시장 · 선택된 디자인 인계

2026-11-10 · 평면 장부 UI + 레트로 능청형 몰래 사장 · 구현 및 브라우저 검증 완료

## 확정 방향

**통통하고 손 내미는 몰래 사장 + 종이 장부·영수증 중심의 평면 UI.** 사용자가 첨부한 캐릭터는 기존 후보 **02번**이다. 화면 시안 04번에 들어 있던 길쭉한 캐릭터와 혼동하지 않는다.

- 실제 사용 캐릭터: `frontend/assets/mollae.png`. 후보 02번 PNG를 변형 없이 복사했다.
- 중절모, 선글라스, 긴 주둥이, 분홍 코, 금니, 초록 앞치마, 빨간 장부를 유지한다.
- 장식은 작은 초록 차양과 종이 도장 정도로 제한한다. 큰 목재 테두리, 황동 장식, 입체 버튼은 사용하지 않는다.
- 면은 크림색 종이, 외상 요약은 진한 초록 장부, 주요 행동은 적갈색 버튼으로 구분한다.
- 캐릭터와 입력 요소는 분리해 읽기 편하게 배치한다. 숫자·업무 목록에는 장식을 겹치지 않는다.

## 확인한 클로드 세션

이 프로젝트의 Claude Code 개발·배포 세션에서 사용자 요청과 최종 작업 내용을 확인했다.

- 기존 작업은 Vercel 프런트엔드 / Render API / Firestore / 외부 AI용 MCP 구조다.
- 서비스 용어는 미래의 시간을 당겨 쓰는 **외상·외상 갚기·갚기 좋은 날**로 통일한다.
- 클로드가 작성한 344줄 README와 MCP 구현을 유지했다. 이번 작업에서 README를 덮어쓰지 않았다.
- 클로드가 예정한 경로에 맞춰 최종 디자인 미리보기는 `docs/design/previews/`에 저장했다.
- 최초 탐색 단계의 6장 이미지는 `docs/design/exploration-previews/`에 보관했다. `screenshots/`는 제출용 실제 화면을 위한 자리다.

## 화면 구성

- 데스크톱: 왼쪽에 몰래 사장과 초록 차양. 오른쪽에 환영 문구, 외상 요약·추천일, 활성 탭의 작업 영역.
- 오늘 할 일: 종이 장부 입력·체크 목록, 오른쪽에 영수증과 예측 습관.
- 캘린더: 기존 증감 색상·추천일 테두리·날짜별 상세 내용을 유지한다.
- 상담: 대화 기록, 선택 캐릭터의 인사, 종이 말풍선, 작은 얼굴 아바타, 빠른 질문, 전송 입력.
- 외상 장부: 수동 기록 폼·필터·표·내보내기 기능을 유지한다.
- 장부 분석: 초록·적갈색 시계열 그래프, 요일·월별 통계를 종이 패널에 표시한다.

| 토큰 | 값 | 사용 |

| `--shop-red` | `#AD382B` | 선택 탭·간판 |

| `--shop-green` | `#46715A` | 초록 차양 |
| `--ink` | `#354C3D` | 장부 요약·내 채팅 |
| `--shop-yellow` | `#E5B853` | 작은 브랜드 포인트 |
| `--text` | `#302B24` | 장부 잉크 |

- 큰 제목·워드마크: Black Han Sans. 본문: Noto Sans KR. 숫자·날짜·작은 영문: IBM Plex Mono.
- Google Fonts 연결 실패 시 시스템 글꼴로 대체한다.
- 다크 모드는 숯빛 올리브, 크림색 글자, 살구색 강조를 사용한다.
- 주요 분기: 1200 / 1000 / 600px. 1000px 이하에서는 사장님 가게를 작은 환영 영역으로 접고, 600px 이하에서는 종이 패널을 세로 배치한다.
- 기본 모서리는 5~8px, 그림자는 얕게. 화면 전체에 두꺼운 테두리를 두르지 않는다.
- 완료·감소는 초록, 증가·주요 행동은 적갈색이며 체크·증감 기호와 문구도 유지한다.

## 기존 기능과 연결할 때

1. `styles.css` 다음에 `shop-theme.css`를 로드한다.
2. 기존 탭·폼·목록·캘린더·차트 DOM ID와 이벤트 선택자를 유지했다.
3. JS 변경은 화면 요소·캐릭터·키보드 탐색·상태 표시 범위다. API 경로와 데이터 처리 계약은 유지했다.
4. 백엔드, MCP, DB, 인증 정보, CORS, `frontend/config.js`, Vercel/Render 배포 설정은 수정하지 않았다.
5. 스크린샷의 데이터는 브라우저에서만 주입했다. 장부 기록 생성·완료·삭제, 실제 AI 요청은 보내지 않는다.
6. 실제 배포와 제출용 화면 촬영은 기존 Vercel/Render 흐름을 이어간다. 완성한 디자인은 기존 GitHub `main`과 Vercel 연동으로 배포한다.

## 미리보기

프로젝트 루트에서 실행한다.

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory frontend
```

- 앱: `http://127.0.0.1:4173/` — 기존 `config.js`의 API 서버가 필요하다.
- 디자인 보드: `http://127.0.0.1:4173/design.html` — 백엔드 없이 확인 가능.
- 최종 구현 이미지: `docs/design/previews/shop-desktop.png`, `shop-mobile.png`, `shop-dark.png`, `shop-chat.png`, `shop-insight.png`, `design-board.png`.

Sites 스킬의 로컬 구현·미리보기 흐름을 적용했다. 새 호스팅 프로젝트나 배포는 만들지 않았다.

## 검증 기록

- Chrome에서 샘플 응답을 사용해 1440px 데스크톱·390px 모바일의 5개 탭, 다크 모드, 이미지 로딩, JS 오류·가로 넘침을 확인했다.
- 320px·768px의 오늘 할 일 화면, 시간 감정 선택지 4개(직접 입력 포함), 완료 시간 입력을 확인했다.
- 방향키·Home·End 탐색과 활성 탭의 단일 포커스, 브랜드 클릭 시 오늘 할 일 복귀, 테마 버튼의 변경된 접근성 이름을 확인했다.
- 샘플 상담 응답에서 사용자·사장 말풍선, 선택 캐릭터 얼굴 아바타, 전송 후 입력 복귀를 확인했다. 대화 예시는 `previews/shop-chat-messages.png`에 저장했다.
- 데이터가 없는 5개 탭과 감정 API 오류 시 직접 시간 입력 폴백, 최종 디자인 보드를 확인했다.
- SVG/XML, 로컬 파일 참조, 중복 DOM ID, 선택 캐릭터 원본 일치, `git diff --check`를 확인했다.
- 장부를 쓰거나 실제 AI를 호출하지 않았다. Firebase·배포 설정은 변경하지 않았다.
- 배포 API를 읽기 전용으로 확인했다. 초기 응답 지연 후 `/health`와 `/api/data/summary`가 HTTP 200을 반환했다. 로컬 미리보기 origin에 대한 CORS 허용 헤더는 없으므로 브라우저 화면 검증은 샘플 응답으로 수행했다. 배포 환경 변수와 API 설정은 유지했다.
